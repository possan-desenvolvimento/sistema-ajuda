💡 O que é o Ecossistema Java?
O ecossistema Java é composto por Java (linguagem e JVM), Maven (gerenciador de dependências) e Spring Boot (framework para aplicações empresariais). Domine esses três pilares para se tornar um especialista back-end.
🧪 Regra de ouro dos testes

Um teste unitário deve ser rápido, isolado e determinístico. Se precisa de banco, rede ou fila real, ele provavelmente é um teste de integração, não unitário.

ESPELHO DE PROJETO

Onde cada coisa mora?

Uma estrutura comum de projeto Spring Boot e a responsabilidade de cada camada.

src/
├── main/java/com/exemplo/app/
│   ├── Application.java
│   ├── controller/       # HTTP e contratos
│   ├── service/          # casos de uso e regras
│   ├── repository/       # acesso a dados
│   ├── model/            # entidades e domínio
│   ├── dto/              # entrada e saída da API
│   ├── mapper/           # conversões entre modelos
│   ├── exception/        # erros e handlers
│   └── config/            # configurações e beans
└── test/java/com/exemplo/app/
    ├── controller/       # testes da camada web
    ├── service/          # testes unitários isolados
    └── integration/      # testes com infraestrutura
Controller

Recebe HTTP, valida entrada e devolve status/DTO. Não deve conter regra de negócio.

Service

Orquestra o caso de uso. É o melhor alvo para testes unitários com mocks.

Repository

Abstrai persistência. Teste queries e mapeamentos com integração quando necessário.

Model

Representa domínio e estado. Entidade JPA não precisa ser o mesmo objeto exposto pela API.

DTO

Define o contrato externo e evita vazar detalhes da entidade.

🏛️ Java - História, JVM, Memória & Tipagem Arquitetura & Base ▶
História: Criado em 1995 (James Gosling / Sun Microsystems) -> Oracle (2010) Origem: Nasceu como "Green Project" e "Oak" para dispositivos inteligentes. Focou em segurança e portabilidade total, tornando-se a espinha dorsal de sistemas corporativos mundiais. Ciclo LTS moderno: 8, 11, 17, 21.
Onde Java é Usado: Fintechs, Bancos, Microsserviços, Big Data (Kafka/Spark), Android O que posso criar: Sistemas bancários de alta concorrência (Pix, cartões), APIs corporativas com Spring Boot, processamento massivo de dados (Big Data), apps Android e plataformas de missão crítica.
Linguagem Estática e Fortemente Tipada: int x = 10; // Não compila se trocar o tipo Fortemente Tipada: NADA no Java existe sem tipo definido. O compilador checa e garante compatibilidade de tipos antes de rodar (type-safety), impedindo erros catastróficos em produção.
Inferência com 'var': var taxa = 0.15; // O tipo double é fixado na compilação var não é tipagem dinâmica: o Java continua 100% estático. O compilador descobre o tipo no ato da atribuição e não permite que a variável mude de tipo depois.
Tríade: JDK (Desenvolvimento + javac) -> JRE (Execução) -> JVM (Máquina Virtual) JDK contém o compilador e ferramentas; JRE fornece as bibliotecas de execução; a JVM executa as instruções do bytecode interpretando e otimizando para o hardware.
WORA: javac MeuApp.java -> MeuApp.class (Bytecode) -> Roda em qualquer SO com JVM Write Once, Run Anywhere: você compila seu código uma única vez para Bytecode (.class) neutro, e a JVM de qualquer sistema operacional (Linux, Windows, macOS, ARM) o executa perfeitamente.
JVM por Dentro: ClassLoader -> Bytecode Verifier -> JIT Compiler (Just-In-Time) Como a JVM roda tão rápido: O JIT Compiler identifica trechos quentes de código repetitivo (hotspots) e compila em tempo de execução diretamente para código de máquina nativo super otimizado.
Memória Stack vs Heap: Stack guarda métodos/primitivos; Heap armazena instâncias (new) Estrutura de Memória: Stack (Pilha LIFO rápida, limpa ao sair do escopo) vs Heap (Memória dinâmica compartilhada onde vivem todos os objetos e arrays criados pela aplicação).
Garbage Collector (GC): Limpeza automática de objetos sem referência na Heap Gerenciamento Automático: O GC rastreia objetos inalcançáveis e libera memória sozinho, eliminando ponteiros manuais, falhas de segmentação (Segmentation Faults) e vazamentos crônicos de memória.
Metaspace & String Pool: Metaspace guarda metadados de classes; Pool reutiliza textos Otimizações Nativas da JVM: Metaspace gerencia definições de classes fora da Heap comum, e a String Constant Pool reaproveita literais de texto para máxima economia de RAM.

🔄 Java - Casting & Conversão de Tipos Essencial ▶
int num = 10; double d = num; // Widening automático (10.0) Widening Casting (Implícito): converte automaticamente um tipo menor para um maior (byte > short > int > long > float > double) sem perda de dados.
double preco = 9.99; int inteiro = (int) preco; // Narrowing (resultado: 9) Narrowing Casting (Explícito): converte manualmente um tipo maior para menor com parênteses. Trunca as casas decimais e pode perder precisão.
int valor = Integer.parseInt("123"); Integer.parseInt: converte uma String contendo dígitos numéricos no primitivo int. Muito usado ao ler parâmetros de formulários e APIs.
double saldo = Double.parseDouble("45.67"); Double.parseDouble: transforma uma representação textual de número decimal para o tipo primitivo double.
String texto = String.valueOf(100); String.valueOf: converte qualquer tipo primitivo ou objeto em sua representação em texto (String) de forma segura contra null.
char letra = 'A'; int codigoAscii = (int) letra; // Retorna 65 Casting char para int: obtém o valor numérico da tabela Unicode/ASCII correspondente ao caractere.
Animal a = new Cachorro(); // Upcasting implícito Upcasting (Polimorfismo): trata uma subclasse como o tipo genérico pai. Sempre é 100% seguro e não exige sintaxe de cast.
Cachorro c = (Cachorro) a; // Downcasting explícito Downcasting: recupera a referência da subclasse para acessar seus métodos específicos. Deve ser validado para evitar ClassCastException.
if (obj instanceof String s) { System.out.println(s.toUpperCase()); } // Java 16+ Pattern Matching com instanceof: checa o tipo do objeto e já declara e atribui a variável com cast automático em uma única linha segura.
🔀 Java - Operadores & Condicionais Iniciante ▶
int resto = 10 % 3; // Operador Módulo (retorna 1) Módulo (%): calcula o resto de uma divisão inteira. Muito utilizado para verificar se um número é par (n % 2 == 0) ou múltiplos.
x += 5; x++; ++y; // Atribuição composta e incremento x += 5 equivale a x = x + 5. Pós-incremento (x++) usa o valor e soma depois; Pré-incremento (++y) soma antes de usar o valor.
if (texto != null && !texto.isBlank()) { ... } E Lógico (&&) com Curto-Circuito: se a primeira condição for falsa, a segunda nem é avaliada, prevenindo erros de NullPointerException.
if (isAdmin || isSuperUser) { ... } OU Lógico (||) com Curto-Circuito: executa o bloco se ao menos uma das expressões for verdadeira.
nome1.equals(nome2) // Comparação de conteúdo vs '==' (endereço de memória) Regra de Ouro: NUNCA use '==' para comparar textos/Strings ou objetos em Java. Use .equals() para comparar o conteúdo real.
String status = (pontos >= 70) ? "Aprovado" : "Reprovado"; Operador Ternário (? :): condicional conciso em uma linha ideal para atribuições baseadas em condições booleanas.
if (media >= 7) { ... } else if (media >= 5) { ... } else { ... } if / else if / else: estrutura clássica para controle de fluxo com múltiplos ramos de decisão encadeados.
String diaTexto = switch (dia) { case 1 -> "Dom"; case 2 -> "Seg"; default -> "Outro"; }; // Java 14+ Switch Expression Moderno: retorna valores diretamente com seta (->) sem precisar de break manual, evitando bugs de queda (fall-through).
int bonus = switch (cargo) { case "DEV" -> 1000; default -> { log.warn("Desconhecido"); yield 0; } }; yield no Switch: devolve um resultado de dentro de um bloco de código multilinhas em uma switch expression.
🔁 Java - Loops & Controle de Fluxo Essencial ▶
for (int i = 0; i < 5; i++) { System.out.println("Índice: " + i); } for tradicional: laço com contador fixo (inicialização; condição de parada; incremento). Ideal quando o total de voltas é pré-determinado.
for (String nome : listaNomes) { System.out.println(nome); } for-each (Enhanced For): itera sobre todos os elementos de arrays e coleções (List, Set) de forma limpa, segura e sem gerenciar índices manuais.
while (sensor.isLigado()) { sensor.lerDados(); } while: executa repetidamente enquanto a condição for verdadeira. A condição é testada no início (pode executar 0 vezes).
do { menu.exibir(); opcao = sc.nextInt(); } while (opcao != 0); do-while: garante que o bloco de código seja executado pelo menos UMA vez antes de verificar a condição de continuidade no final.
if (encontrado) break; // Interrompe o loop imediatamente break: aborta a execução do laço de repetição imediatamente, transferindo o fluxo para a linha seguinte fora do loop.
if (item.isNulo()) continue; // Pula para a próxima iteração continue: interrompe a iteração atual e avança direto para a próxima volta do laço sem executar as linhas restantes do bloco.
externo: for (int i = 0; i < 10; i++) { for (int j = 0; j < 10; j++) { if (achou) break externo; } } Labeled Loop (Rótulo): permite que um break ou continue atue diretamente sobre um loop pai em laços aninhados profundos.
return resultado; // Finaliza o método e entrega a resposta return: encerra imediatamente a execução do método atual e devolve o valor para quem o invocou.

public static final double PI = 3.14159; Math.sqrt(25); Membros Estáticos (static): pertencem à própria classe e não a uma instância individual. Podem ser chamados diretamente sem instanciar com new.

⚠️ Java - Tratamento de Exceções Intermediário ▶
try { int res = 10 / 0; } catch (ArithmeticException e) { System.err.println(e.getMessage()); } try-catch: intercepta e trata erros em tempo de execução, impedindo que a aplicação trave de forma inesperada.
try { ... } catch (IOException | SQLException e) { log.error("Falha de I/O ou BD", e); } Multi-Catch: captura múltiplos tipos de exceção no mesmo bloco usando pipe (|), evitando repetição desnecessária de blocos de tratamento.
try { ... } finally { conexao.close(); } finally: bloco que SEMPRE é executado após o try ou catch, mesmo se houver erro ou return antecipado. Ideal para limpar recursos.
try (var reader = Files.newBufferedReader(path)) { String linha = reader.readLine(); } try-with-resources: fecha automaticamente conexões, arquivos e streams que implementam AutoCloseable ao fim do bloco.
if (saldo < valor) { throw new SaldoInsuficienteException("Saldo insuficiente"); } throw: lança intencionalmente uma exceção quando uma regra de negócio ou pré-condição do sistema é violada.
public void processar() throws IOException { ... } throws: declara na assinatura do método que ele pode propagar uma Checked Exception, obrigando o chamador a tratá-la com try-catch.
public class RegraNegocioException extends RuntimeException { public RegraNegocioException(String msg) { super(msg); } } Exceção Customizada: herda de RuntimeException para representar falhas de regras de negócio em arquiteturas modernas.
